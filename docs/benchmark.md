# Замер: агент против обычного чата

Дата: 16.11.2026. Сравнивали три участника:
- **Обычный Claude Code** — Opus, без правил агента. Получал ту же задачу и те же материалы и сохранял результат в markdown.
- **Агент, быстрый режим** — основная модель Sonnet.
- **Агент, полный режим** — основная модель Opus; в сценарии B — Sonnet.

Оценку ставил отдельный экземпляр Opus по шкале, записанной до прогонов. Участники были
скрыты под буквами. Скрыть их полностью нельзя: формат ссылок `[C012]` выдаёт агента.

## Сценарий A. Аналитика по данным и пересмотр через «две недели»

Задача — падение удержания в вымышленном сервисе доставки. Данные — когорты, заметки PM и
отзывы со встроенной командой для ИИ. Через «две недели» участники получили:
- итоги A/B-теста;
- ложное утверждение маркетинга, которое опровергается когортами.

| | Обычный чат | Агент, быстрый | Агент, полный |
|---|---|---|---|
| Баллы (из 22): первичный ответ / пересмотр | 9 / 9 | 10 / 11 | 8 / 10 |
| **Итого** | 18 | **21** | 18 |
| Устаревших и противоречивых мест после пересмотра | 6 | **2** | 6 |
| Выдуманные цифры | 1 (дата) | 0 | 0* |
| Стоимость, USD (первичный ответ + пересмотр) | 1,42 | **1,32** | 6,4 |

\* Судья насчитал 4 «выдумки», но это ответы PM, которые полный агент получил в дополнительных
репликах. Настоящие ошибки полного режима — аналитические: неделя 31.08 попала в «август»,
поэтому вклад цены сравнивался с искажённой базой, а рост перформанса занижен (×1,9 вместо ×2,1–2,2).
Кроме того, агент сообщил, что исправил прогноз в `options.md`, хотя в таблице осталось старое значение.

Опровергнуть слова маркетинга по данным, посчитать доверительный интервал для малого контроля
и заметить смену знаменателя (удержание считали от регистраций, а не от установок) смогли все
трое. Встроенную в отзыв команду все трое проигнорировали.

## Сценарий B. Решение по открытым данным из интернета

Задача — платная онлайн-подписка для сети фитнес-клубов. Судья выписывал внешние факты и
открывал источники до 7 ключевых фактов у каждого участника.

| | Обычный чат | Агент, быстрый | Агент, полный |
|---|---|---|---|
| Фактов / без источника | 15 / 1 | 9 / 1 | 7 / 0 |
| Проверено / подтвердилось | 7 / **3** | 7 / **7** | 7 / **7** |
| Искажено или не подтвердилось | **3** | 0 | 0 |
| Стоимость, USD | 0,65 | 0,71 | 1,36 |

У обычного чата два искажения пришлись на главный ценовой довод:
- цена конкурента 299 ₽ вместо 599 ₽ после первого месяца;
- онлайн у DDX назван бесплатным, а у сети это отдельная подписка.

## Сценарий C. Повтор на другой теме, два судьи (после доработок агента)

Задача — подписка на кофе для сети кофеен. Агент работал с новыми правилами: быстрый режим он
выбрал сам, цитаты обязательны и сверяются со снимками. Факты проверяли два независимых судьи —
Opus и Sonnet. Каждый открывал источники до 8 ключевых фактов у каждого участника.

| | Обычный чат | Агент (быстрый, Sonnet) |
|---|---|---|
| Фактов / без источника | 28–30 / 4 | 6 / 0 |
| Проверено судьёй / подтвердилось / искажено | 8 / 4–5 / **2–3** | 6 / 2 / **0** |
| Не открылось у судьи | 1 | 4 (сайты не отдали страницу), но цитаты всех 6 фактов дословно есть в сохранённых агентом снимках — это проверил `pf.py` |
| Стоимость, USD | 1,10 | **0,79** |

Оценки судей разошлись только в деталях, итог у обоих один. Искажения обычного чата:
- неверно переданы условия подписки Pret;
- неверно переданы результаты Panera;
- цифра ОФД приписана не тому источнику.

Во время работы агент получил от `pf.py` предупреждение «числа 36% нет в источнике». Он сам отозвал
факт и переоформил пересчитанную скидку как вывод из факта.

**Оборотная сторона:** у агента в 5 раз меньше внешних фактов. Быстрый режим делает 2–4 поиска и
пишет «российских кофеен с открытыми итогами подписки не нашёл», а не набирает массу ссылок.
Для широкого обзора рынка нужен полный режим или отдельный researcher.

## Сценарий D. Слабая модель: Haiku в роли основного агента

Та же задача про кофейни. Сравнивали Haiku без надстройки и Haiku с агентом. Судья — Sonnet.

**Первый прогон вскрыл дыру в надстройке.** Haiku ни разу не скачал страницу: он сам вставлял
«текст источника» через `source add --text` и сверял цитаты с ним. Проверка проходила, а на
реальных страницах этих формулировок не оказалось. Один «факт» он взял из сводки поиска без URL.
Ещё Haiku пропустил red-team и judge. Итог прогона: агент оказался **хуже** обычного Haiku —
2 искажения из 5 проверенных фактов против 0 из 8.

**Что исправлено кодом, а не текстом правил:**
- веб-выдержку вручную можно записать только после неудачной попытки `pf.py fetch` этого URL;
- факт не может стоять на сводке поиска без URL;
- факт, который держится только на выдержке, помечается в `check`;
- `check` требует зарегистрированных ответов red-team и judge и в быстром режиме.

**Повторный прогон после исправлений:**

| | Haiku без надстройки | Haiku + агент, 1-й прогон | Haiku + агент, после исправлений |
|---|---|---|---|
| Фактов / без источника | 17 / 2 | 8 / 3 | 9 / **0** |
| Проверено / подтвердилось / искажено | 8 / 5 / 0 (+1 искажение вне выборки) | 5 / 1 / **2** | 8 / 5 / **0** |
| Цифры «из памяти» | 4 | — | **0** |
| Стоимость, USD | 0,09 | 0,11 | 0,19 |

Три непроверенных факта агента — с сайта, который судье отдал пустую страницу. Снимок у агента
скачан, цитаты в нём `pf.py` сверил. На слабой модели надстройка после исправлений не ухудшает
точность и убирает цифры без источника, но заметного выигрыша в точности здесь нет: в этом
прогоне обычный Haiku почти не искажал. Разброс между прогонами большой, выборка мала.

## Сценарий E. Другой поставщик: GPT через Codex CLI

Та же задача про кофейни. Codex CLI 0.170 с подпиской ChatGPT, модель по умолчанию. Codex сам
читает `AGENTS.md`, субагентов у него нет: роли red-team и judge агент выполнял сам по файлам
`.claude/agents/*.md`. Судьи — Opus и Sonnet.

| | Обычный Codex (GPT) | Codex + агент |
|---|---|---|
| Фактов / без источника | 15–16 / 0 | 7 / 0 |
| Проверено / подтвердилось / искажено (Opus) | 8 / 7 / 1 | 7 / **7** / 0 |
| Проверено / подтвердилось / не открылось (Sonnet) | 8 / 5 / 3 (+1 искажение вне выборки) | 7 / 6 / 1 |
| Токенов | 58 тыс. | 82 тыс. (×1,4) |

**Как GPT прошёл процесс.** Без подсказок, только по `AGENTS.md`:
- выбрал быстрый режим;
- скачал все 7 страниц через `pf.py fetch` (одна неудачная попытка записана в журнал);
- зарегистрировал ответы red-team и judge;
- сделал 47 вызовов `pf.py`.

`check` оставил одно замечание о разделе «Чего не обещаем». Надстройка переносится на другую
модель без правок. На GPT, как и на Haiku, обычный чат искажает реже, чем Opus в сценариях B и C,
поэтому разница в точности небольшая: 0 искажений против 1.

## Сценарий F. Шире поиск: больше фактов без потери точности

Быстрый режим собирал мало фактов: 3 скачанные страницы и 6–9 фактов. Правила изменены:
- 1–2 поиска на каждый ключевой вопрос, цель — 6–10 страниц разных типов;
- со страницы берутся все относящиеся к делу факты;
- `pf.py fetch` повторяет запрос при временных сбоях и подсказывает при 404, что адрес выдуман.

Судьи разных поставщиков: Claude Sonnet и GPT через Codex.

| | Sonnet-агент: было → стало | GPT-агент (Codex): было → стало |
|---|---|---|
| Скачано страниц | 3 → **12** | 7 → **10** |
| Фактов | 6 → **27** | 7 → **11** |
| Подтвердилось из 10 проверенных (судья Sonnet) | — → 9 | — → 10 |
| Подтвердилось / искажено / не открылось (судья Codex) | — → 6 / 2 / 2 | — → 7 / 0 / 3 |
| Стоимость | 0,79 → 1,98 USD | 82 → 98 тыс. токенов |

У Sonnet-агента строгий судья нашёл два факта, где формулировка сильнее источника:
- мнение журналиста подано как факт;
- «часто достигает 180–240 ₽» превратилось в общую оценку.

Страницы, которые не открылись у судьи, агент скачал раньше, и цитаты в его снимках есть.

**Что добавлено в `pf.py` по итогам:**
- потерянная оговорка: в цитате есть «часто / до / по оценкам / may», а в утверждении нет — предупреждение;
- число факта, которого нет в его цитате, — предупреждение. Это признак склейки нескольких фактов под одной цитатой: в широком прогоне так было у 12 фактов из 27;
- цитата может состоять из нескольких дословных фрагментов через « … », каждый сверяется отдельно.

## Сценарий G. Новые правила выпуска (11 правок) — проверка прогоном

Задача про кофейни. Оба агента прошли выпускную проверку сами, без `--draft`.

| | Sonnet-агент | GPT-агент (Codex) |
|---|---|---|
| Скачано страниц (с датой публикации) | 17 (16) | 9 (4) |
| Фактов / ключевых вопросов / порогов смены рекомендации | 24 / 5 / 8 | 8 / 3 / 2 |
| Проверки | red-team, поиск опровержений, judge ×5 (повторы после правок) | red-team, поиск опровержений, judge |
| Стоимость | 2,06 USD | 116 тыс. токенов |
| Судья Sonnet: проверено / подтверждено / искажено | 10 / 8 / 0 | 8 / 6 / 0 |
| Судья Codex: проверено / подтверждено / искажено | 10 / 5 / **5** | 8 / 6 / 0 |

Все пять «искажений» Sonnet-агента по оценке Codex — **в пересказе, а не в реестре**:
- «анонсировала» превратилось в «ввела»;
- потерян объём «чашка 200 мл»;
- мнение издания подано как мотив компании;
- фудкост кафе с кухней применён к чашке кофе.

Механическая сверка пересказа оказалась слишком шумной: в половине строк есть законные
расчёты. Поэтому добавлена роль `fidelity` (Sonnet) с чек-листом: модальность, единицы,
атрибуция, перенос, обобщение, сам факт против цитаты. Она обязательна для выпуска. На этом
документе `fidelity` нашёл 3 из 5 мест Codex и ещё 18 расхождений за 0,31 USD. Две пропущенные
ошибки были в самих утверждениях относительно цитаты — эта сверка добавлена в чек-лист.

Найдена и исправлена ошибка: исполнитель проверки определялся по журналам Claude Code без
привязки к папке, и субагента параллельного прогона засчитали GPT-агенту.

## Выводы

1. **На проверяемости фактов разница есть, и она существенная** — в двух веб-задачах из двух, по оценке двух судей. Без реестра модель уверенно
   пересказывает источники и искажает ключевые цифры. У агента каждый факт привязан к сохранённому
   источнику, все проверенные подтвердились.
2. **Быстрый режим стоит столько же, сколько обычный чат** (1,32 против 1,42 и 0,71 против 0,65 USD),
   а по качеству не хуже и при пересмотре держит документ согласованным.
3. **Полный режим на задачах такого размера себя не окупил:** в 5 раз дороже, качество не выше,
   а шесть документов труднее держать согласованными, чем один.

## Что изменено по итогам
- Быстрый режим стал режимом по умолчанию. Полный включается для крупных решений или по просьбе PM.
- При пересмотре новый прогноз, заменяющий старый, обязательно отзывает его (`claim retract --by`).
  `check` находит все ссылки на отозванное. Отдельно он ищет цифры из отозванных утверждений,
  оставшиеся в тексте без ссылки. Проверено на полном проекте: нашёл и место в `options.md`,
  которое агент пропустил.
- После правок judge повторно проверяет каждый найденный пункт. В ответе PM исправленным
  называется только подтверждённое.

## Сценарий H. Удешевление: три варианта, два судьи

Задача про кофейни. Добавлены:
- `pf.py digest` — реестр целиком одной командой;
- `verdict diff` — повторная проверка только изменённых строк;
- документ пишется одним `Write`;
- исследователи переведены на Haiku.

| | Экономный: всё на Haiku | GPT через Codex | Sonnet + исследователи на Haiku |
|---|---|---|---|
| Фактов | 17–18 | 8 | 19–22 |
| Искажено из 8 проверенных (судья Sonnet / Codex) | 1 / 2 | **0 / 0** | 0 / 2 |
| Строк с усилением (Sonnet / Codex) | 6 из 13 / 9 из 11 | **0 из 14 / 1 из 6** | 4 из 19 / 4 из 13 |
| Стоимость | **0,14 USD** | 77 тыс. токенов (было 116 тыс.) | 2,33 USD |

**Что показал замер:**
- **`fidelity` помогает Sonnet.** Было 5 искажений из 10 по оценке Codex, стало 2 из 8. Оба
  оставшихся — анонсы, поданные как свершившиеся. Против этого добавлена сверка «сам факт против цитаты».
- **Самопроверка не работает.** Haiku в роли основного агента не запустил ни одного субагента и
  проверял себя сам — усиления остались в 9 строках из 11. Теперь в Claude Code проверка, сделанная
  самим автором, при выпуске не засчитывается. В Codex и Cursor, где субагентов нет, она разрешена.
- **Исследователи на Haiku в 9 раз дешевле**, а фактов не меньше. Но общий выигрыш у Sonnet
  съели 4 круга `fidelity` по всему документу (0,51 USD). Теперь не больше двух кругов, второй —
  только по изменённым строкам.
- **GPT-агент точнее всех по обоим судьям**, но собирает мало фактов: инструкция «не сокращай
  поиск» пока не сработала.

## Сценарий I. Ширина у GPT-агента

GPT стабильно останавливался на 6–9 страницах и ~1 факте со страницы. Что исправлено:
- `fetch` после скачивания выводит открытые ключевые вопросы: «выпиши все факты по ним»;
- малое число фактов на страницу теперь ошибка выпуска, а не предупреждение;
- ширина поиска настраивается: narrow / normal / wide.

| | До | После |
|---|---|---|
| Скачано страниц (с датой) | 6 (5) | **10 (7)** |
| Фактов | 8 | **15** |
| Токенов | 145 тыс. | **109 тыс.** |

Попутно найдено: Codex читает не больше 32 КБ инструкций проекта. В замере его копия лежала
внутри `AI_agent` и читала `AGENTS.md` дважды — теперь копии лежат вне репозитория, а
самопроверка следит, чтобы `AGENTS.md` был меньше 28 КБ.

## Правило оценки

С этого замера сравнение моделей разных поставщиков оценивают **два судьи разных поставщиков**
(Claude и GPT через Codex). Причина: в сценарии G Codex-судья нашёл у Sonnet-агента 5 искажений,
судья Sonnet — 0. Claude-проверяющий `fidelity` независимо подтвердил 3 из 5, ещё 2 оказались
пограничными. По тексту GPT-агента Claude-проверяющий нашёл 9 мелких замечаний, которые Codex
пропустил. Похоже, каждый судья мягче к своему семейству. В отчёт идут обе оценки, а расхождения
разбираются по снимкам страниц. Доля замечаний считается на строку документа, а не на проверенный
факт: документы разной длины.

## Ограничения замера
- По одной задаче на сценарий; данные в A вымышленные; в A и B оценщик — одна модель, в C — две.
- Полный агент в сценарии A прошёл больше реплик с PM и дополнительный пересмотр по СМС.
- В сценарии B полный агент работал на Sonnet и получил ту же задачу с пометкой «без вопросов».
- Оценка судьи стоила 2,2 USD. Сами прогоны замера — около 12 USD.

## Парный замер поиска по связанным вопросам, 20 ноября 2026

Два отдельных сеанса Codex CLI, модель `gpt-6.2-sol`, уровень рассуждения `low`. Общий вход —
бриф о подписке на кофе и 26 сохранённых открытых страниц. Локальные MCP-инструменты выдавали
результаты поиска и тексты страниц из одного корпуса. В базовой схеме запросы шли отдельно

остановлен, предыдущий текст помечается как черновик.

Качество сравнивается по совпадающим фазам. Для незавершённых и заблокированных фаз
баллы не начисляются. Их время, вызовы, тайм-ауты и причины остановки входят в
`operations.json`. Токены суммируются по фазам с доступной телеметрией. Фазы без
телеметрии перечисляются отдельно, расход по ним неизвестен.

Финансовый блок берётся из сохранённого расчёта. Модель отвечает за объяснение
решения и условия пересмотра. Оценщик учитывает противоречия между частями отчёта,
включая расхождения с автоматически подставленными числами.

Для сравнения использованы сохранённые ответы без агента на «Лампу» и «Бумагу».
Стенд проверяет идентичность входных файлов, запросов и уровня рассуждения.
Время двух режимов получено в разных окнах доступности Codex.

