# Стратег Фабрики продуктов

ИИ-агент для руководителя цифрового продукта: от размытого запроса — к проверяемой картине
ситуации, нескольким разным вариантам и согласованным продуктовой и коммуникационной
стратегиям с планом проверки; после решения — сопровождение и пересмотр при новых данных.

Агент — это папка: инструкции (`AGENTS.md`), процедуры (`.claude/skills`), помощники
(`.claude/agents`), методики (`knowledge/`), инструмент учёта доказательств (`tools/pf.py`)
и проекты (`projects/`). Открывается в Claude Code (основная среда), Cursor или Codex.

## Быстрый старт

### Codex на Windows

Откройте папку репозитория в Codex и запустите `.\pf.ps1` в PowerShell 7 из корня папки.
Из старого Windows PowerShell можно вызвать PowerShell 7 командой `pwsh -NoProfile -File .\pf.ps1`.

Скрипт покажет активный проект и следующее действие. Он найдёт установленный Python 3.10+,
включая локальное окружение `.venv` или Python из комплекта Codex. Если Python недоступен,
установите его. Для чтения PDF и XLSX установите пакеты из `requirements.txt`.
Через тот же скрипт можно вызвать любую команду, например `.\pf.ps1 check`.

В чате опишите решение, которое нужно принять, и приложите исходные файлы. Для репетиции
используйте [сценарий «Сигнал Плюс»](examples/signal-bundle/README.md). После паузы откройте
новый чат Codex в той же папке и напишите «Продолжим активный проект». Агент прочитает статус,
следующее действие и журнал проекта с диска.

### Claude Code

Требования: Python 3.10+, Claude Code (подписка Claude Pro/Max или ключ API Anthropic).
Других платных сервисов не требуется. Секреты в репозитории не хранятся.

```bash
git clone <repo> && cd <repo>
pip install -r requirements.txt      # опционально: PDF и XLSX
mkdir -p .claude && cp docs/claude-settings.proposed.json .claude/settings.json   # хуки и разрешения
claude                               # запустить Claude Code в корне репозитория
```
В чате: `/pf-start` и опишите задачу своими словами, например:
«Удержание в нашем приложении упало за полгода, надо понять, что делать. Вот выгрузка» —
и приложите файлы. Агент сам задаст нужные вопросы и поведёт работу по этапам.

Продолжить после перерыва (в том числе в новом чате): просто откройте `claude` — хук
покажет статус и следующее действие; или `/pf-start` → «продолжим».

**Cursor / Codex:** откройте папку; правила подхватываются из `AGENTS.md` / `.cursor/rules`.
Попросите агента «начни новый проект» или «продолжи».

**MCP** (`tools/mcp_server.py`, только стандартная библиотека). Инструменты поверх `pf.py`:
`pf_status`, `pf_fetch`, `pf_source_read`, `pf_focus`, `pf_ingest`, `pf_claim_add`, `pf_check`, `pf_impact`, `pf_kb_search`… и `pf`
для любой другой команды. Каждый вызов запускает `pf.py`, поэтому проверки, блокировка и журнал
те же. Cursor подключает сервер из `.cursor/mcp.json` (Settings → MCP → включить `pf-strategist`).
Codex — в `~/.codex/config.toml`:
```toml
[mcp_servers.pf-strategist]
command = "python3"
args = ["/полный/путь/к/репозиторию/tools/mcp_server.py"]
```
В Windows укажите в `command` полный путь к установленному `python.exe`, если `python3` недоступен.
Пути Windows в TOML можно заключать в одинарные кавычки.

В Claude Code сервер не подключён намеренно: там те же действия делают skills и `pf.py` через Bash,
а второй набор инструментов только путал бы модель.

## Как это устроено

```
Запрос PM ─► intake ─► collect ─► research ─► options ─► [PM выбирает] ─► strategy ─► validation ─► decision ─► tracking
                │          │          │           │                          │            │             │           │
           ключевые    реестр S   реестр C/G   варианты +              продукт +     план проверки   решения D   pf.py review /
           вопросы Q   (снимки,   situation.md red-team               коммуникации                   + отчёт     impact / revise
                       sha256)                                        + сверка judge
```

| Слой | Где | Что |
|---|---|---|
| Постоянные правила | `AGENTS.md`, `CLAUDE.md` | принципы, процесс, маршрутизация, безопасность |
| Процедуры этапов | `.claude/skills/pf-*` | пошаговые инструкции, вызываются как `/pf-...` |
| Помощники | `.claude/agents/*` | researcher (Sonnet), source-extractor (Haiku), data-analyst (Sonnet), red-team (Opus), synthetic-respondent (Haiku), judge (Haiku) |
| Методики | `knowledge/methods/` | стандарты доказательности, стратегии, интервью, данные, UX |
| Шаблоны результатов | `knowledge/templates/` | situation, options, стратегии, план проверки, summary |
| Материалы и состояние задачи | `projects/<slug>/` | state.json, STATUS.md, journal.md, sources/, evidence/, decisions/, deliverables/ |
| Инструмент | `tools/pf.py` | реестры, проверки, влияние изменений, стоимость, отчёт |

### Реестр доказательств
- **Источники `S…`** — веб-страницы, файлы PM, интервью, расчёты; снимок + извлечённый текст +
  sha256 + дата получения; проверка на попытки prompt-injection.
- **Утверждения `C…`** — тип (`fact` / `hypothesis` / `forecast` / `assumption` / `synthetic`),
  источники, место в источнике, цитата, уверенность, из чего выведено. Факт без источника не
  записывается. Отзыв (`retract`) не удаляет, а помечает — история сохраняется.
- **Пробелы `G…`**, **ключевые вопросы `Q…`**, **решения `D…`** с ответственными, метриками,
  основаниями, обязательствами и датами пересмотра.
- В документах ссылки `[C012]`; `pf.py check` находит битые и отозванные ссылки, факты без
  источников, синтетику в роли доказательства спроса.
- **Механическая сверка фактов:** цитата факта должна дословно найтись в сохранённом тексте
  источника, иначе факт не записывается; числа факта, которых нет в источнике, дают
  предупреждение (так ловятся пересказ «по памяти» и искажённые цифры — без участия модели).
- `claim add` и `check` также предупреждают о некоторых усилениях пересказа: верхняя граница
  стала точным числом или запланированное событие описано как состоявшееся. В итоговых документах
  диагностика показывает строку, когда её можно связать с одним утверждением `[C…]`.
- **Выпуск только через проверку:** отчёт и переход к выбору/решению блокируются, пока у
  фактов в документах нет цитат, числа не сходятся с цитатой, ключевые вопросы без ответа или
  пробела, пункты «Почему» без ссылок, нет проверок red-team, judge и поиска опровержений по
  текущей версии документа. Реестр пишется под блокировкой — параллельные субагенты не теряют
  записи (без неё из 12 одновременных записей уцелели 2).
- `pf.py impact --claim C005` — какие выводы, строки документов, решения и вопросы затронуты:
  по прямым ссылкам, по тегам (пробелы и вопросы, которые закрывало утверждение) и по
  основаниям решений; документы без прямых ссылок перечисляются для ручного просмотра.
- В новых итогах и вариантах таблица «Сверка оснований рекомендации» связывает решающий вывод с
  действующим утверждением или открытым пробелом, проверкой и условием смены решения.
  `check --release` проверяет заполнение таблицы и ссылки.
- `check` также предупреждает о допущениях, на которые никто не ссылается (их отзыв нельзя
  отследить), о ссылках на отозванное в пробелах и решениях и об отсутствии независимой
  сверки обещаний (judge).
- При пересмотре субагент `judge` сверяет все документы с актуальным состоянием — ловит
  остатки старой картины, в том числе от прошлых пересмотров.

### Основные команды
```
python3 tools/pf.py status            # где мы
python3 tools/pf.py claim list        # на чём основаны выводы
python3 tools/pf.py focus --q Q001    # уже собранные факты и открытые пробелы по вопросу
python3 tools/pf.py source read --id S001,S002 --seen S001  # прочитать S002, если S001 уже в контексте
python3 tools/pf.py fetch https://example.com --reuse       # взять снимок для этого URL, если он уже есть
python3 tools/pf.py check             # целостность ссылок
python3 tools/pf.py review            # что пора пересмотреть
python3 tools/pf.py decision edit --id D003 --trigger "..." --note "почему"   # уточнить решение (с историей)
python3 tools/pf.py gap edit G002 --new-text "..." --reason "..."            # уточнить пробел
python3 tools/pf.py source reviewed --id S003 --note "..."                   # подозрительный фрагмент разобран
python3 tools/pf.py cost              # сколько стоило (по журналам Claude Code)
python3 tools/pf.py report --html     # итоговый отчёт
python3 tools/pf.py check --release   # выпускная проверка (её же проходят report и переход к выбору)
python3 tools/pf.py verdict add --role judge --target deliverables/summary.md --text "..."  # проверка документа и его оснований
python3 tools/pf.py verdict context --target deliverables/summary.md  # документ и полные цитаты одним вызовом
python3 tools/pf.py verdict diff --role fidelity --target deliverables/summary.md --evidence  # правки и выводы, чьи основания изменились
python3 tools/pf.py batch analysis/registry_batch.txt --quiet          # результаты и предупреждения без повтора команд
python3 tools/pf.py source date --id S003 --published 2025-04-01      # дата публикации (свежесть)
python3 tools/pf.py claim switch C012 --range "3..8%" --switch "при <3% → вариант A"  # порог смены рекомендации
python3 tools/pf.py kb search "отток после повышения цены"   # база знаний прошлых проектов
python3 tools/pf.py kb use K004       # перенести запись в проект с честным статусом
python3 tools/selftest.py             # самопроверка pf.py (для разработчика агента)
python3 tests/smoke_test.py           # смоук-тест гарантий реестра во временной папке, без сети и моделей
```

При выпуске отчёта изменение процитированного основания требует новой проверки, даже если текст
остался прежним. `verdict diff --evidence` показывает изменившиеся записи и затронутые строки.
Для старых вердиктов без отпечатков оснований выводится предупреждение. Нужна полная сверка,
чтобы записать первый вердикт с основаниями.

Для предварительной проверки ценового пилота подписки используйте
`python3 tools/pilot_economics.py --help`. Калькулятор сравнивает вклад на назначенного
пользователя, показывает порог продления и проверяет, достижим ли паритет при заданных
ценах и расходах. Если расходы неизвестны, он сравнивает подписочную выручку.

Чтобы привязать расчёт к решению, используйте `decision pilot`. Основания условий,
например цены и горизонт, передаются через `--fixed-basis`. Основание контрольного
продления передаётся через `--basis`. После поправки достаточно передать обновлённое
значение и его основание. `decision show --id D001` показывает результат и его статус.
`report --html` выводит финансовый допуск в начале Markdown и HTML. В авторском тексте
объясните влияние расчёта на решение и сошлитесь на [D001]. `verdict context` показывает
тот же финансовый блок, а его изменение требует повторной сверки перед выпуском.
Для выпуска можно одним вызовом записать результаты отдельных проверок через
`verdict add --target … --review РОЛЬ "вывод" … --check-release`.

При пересмотре сначала зарегистрируйте поправку через `ingest`. Затем
`revision-packet --id D001 --source S002 --review-rules` соберёт решение, связанные
утверждения, прежний текст, новые источники и правила сверки в один пакет.
Команда читает состояние проекта. Пересчёт и выпуск выполняются обычными командами.

`revision-packet` подходит и для решений без сохранённого финансового расчёта.
В `revision-packet --compact` сохранены порог и условия, действующие и заменённые
основания и выдержки с соседними строками. При необходимости откройте указанный
полный снимок по ID через `source read`.
После записи поправки `revision-card --id D001 --source S007` показывает, что
отозвано, на каких фактах основана новая версия и какие разделы затронуты. Пока
решение опирается на отозванные сведения, карточка запрашивает сверку. Решение
подтверждает PM. [Пример для запуска и записи экрана](examples/signal-bundle/README.md)

### Основания и покрытие вопросов

При подготовке отчёта передайте `pf_foundations` через MCP массив строк таблицы
в виде JSON-строки в поле `json`.
`conclusion` содержит вывод, `refs` — ID действующих утверждений или открытых
пробелов, `counter` — чем проверить вывод, `revisit` — когда менять решение.
С параметром `target: "deliverables/summary.md"` команда обновляет только таблицу
в сохранённом документе. Без `target` она выводит Markdown. В CLI это
`foundations --target deliverables/summary.md` с JSON из stdin или через `--json`.
Проверки актуального документа выполняются после сборки таблицы.

Для сбора фактов по вопросу из уже сохранённых снимков используйте
`research-evidence --q Q001 --source S001,S002 --position "Проверяемая гипотеза" --extract`.
Codex CLI извлекает кандидатов через Luna и вызывает Sol для повторной сверки,
если есть встречные сведения, ошибки в цитатах или нет подтверждения по
важному вопросу. Результат показывает факты-кандидаты, цитаты, периоды, единицы
и причину проверки. В других средах команда без `--extract` или `--json` выдаёт
запрос для текущей модели. Ответ можно сверить локально через `--json -`.

После проверки запишите принятые факты через `claim add` с цитатой, ID вопроса и
`--evidence-role support` или `--evidence-role counter`. `focus --q Q001`
показывает обе стороны, цепочки пересказов и незакрытые пробелы. Команды
`pf_research_evidence`, `pf_claim_add` и `pf_focus` доступны в MCP.

### Пересчёт пилота из CSV

Для поправки к продлению сохранённого пилота создайте шаблон и откройте его в редакторе
таблиц. Шаблон привязан к текущей версии расчёта в выбранном проекте.

```powershell
.\pf.ps1 pilot-triage --id D001 --csv-template .\popravka.csv
```

1. В `period_0` укажите число участников при назначении. В `period_1`, `period_2`
   и следующих строках укажите число оплаченных подписок после каждого продления.
2. Поставьте `да` в `same_control_cohort` и `conditions_unchanged`, если выгрузка
   относится к прежней контрольной когорте и цены, затраты, число периодов и
   финансовый порог остались прежними. Это подтверждение автора выгрузки.
3. Заполняйте `control_renewal_pct` только при наличии в выгрузке постоянного сценария
   для округлённых наблюдений. Пишите число без знака процента. Пустое поле означает,
   что доли по всем переходам должны совпадать. Сохраните CSV в UTF-8.

```powershell
.\pf.ps1 pilot-triage --id D001 --file .\popravka.csv
```

Команда сверяет версию пилота, полноту ряда и согласованность чисел. Подтверждённый
постоянный сценарий может расходиться с наблюдением максимум на одного участника
на переход. При успехе команда регистрирует CSV как источник и выводит старый и
новый расчёт с финансовым допуском. Всё выполняется локально без модели. При
изменении когорты или условий нужен полный пересмотр. Для текста в `--file`
используется Codex, результат требует ручной сверки всего источника.

Записка предназначена для проверки руководителем. Обновление решения и выпуск
отчёта проходят обычное согласование.

### База знаний между проектами
`projects/_kb/kb.jsonl` — то, что стоит помнить после проекта: факты с исходными источниками
(`kb promote Cxxx`), выводы агента (`kb add --kind lesson`), прошлые решения (`kb promote Dxxx`),
слова человека (`kb add --kind note`). В новом проекте запись становится тем, чего заслуживает
её происхождение: факт — фактом с тем же источником и предупреждением о давности, вывод агента —
только гипотезой, решение и слова человека — допущением. Поиск — по основам слов и триграммам
(русская морфология без словарей), навигация — теги и связи (`kb related`), исправление —
`kb retract` / `kb supersede` с историей; проекты, взявшие отозванную запись, увидят это в
`pf.py check`. Подробно — `AGENTS.md`, §8.

### Хуки Claude Code
- `SessionStart` → статус активного проекта (продолжение без повтора шагов).
- `PreToolUse` → запрет правки правил/инструментов агента во время работы (защита от команд
  из источников). Для разработки агента создайте пустой файл `.dev_mode`.
- `Stop` → `pf.py check` после каждого ответа. При ошибках целостности (ссылка на отозванное,
  факт без источника, синтетика как факт) хук не даёт закончить ответ и передаёт ошибки
  агенту — один раз за ответ, без зацикливания. Предупреждения ответ не блокируют.

## Режимы и замер качества
- **Быстрый (по умолчанию):** один документ `summary.md` с вариантами, условной стратегией,
  сверкой обещаний и планом проверки; основная модель — Sonnet. **Полный:** шесть документов
  этапов, остановка на выборе, Opus. Подробно — `AGENTS.md`, раздел 3а.
- Замер против обычного чата — `docs/benchmark.md`. На веб-задаче из 7 проверенных фактов у
  обычного чата подтвердились 3, у агента — 7. Быстрый режим стоил столько же, сколько
  обычный чат (1,32 против 1,42 USD), и после пересмотра оставил 2 устаревших места против 6.
- Как агента тестировали и чинили — `docs/overnight_report.md`.

## Ограничения
- Работа с сайтами: `pf.py fetch` не исполняет JavaScript — для таких сайтов агент использует
  WebFetch среды. Сайты с авторизацией не поддерживаются намеренно.
- Изображения анализируются моделью напрямую; аудио/видео — через расшифровку и кадры,
  которые готовятся вне `pf.py` (см. `docs/media.md`).
- Параллельные вызовы `pf.py` (субагенты) безопасны: хранилище блокируется на время команды
  (`projects/.lock`); загрузка страницы в `fetch` идёт вне блокировки.

Проверяет: факт без источника отклоняется, инъекция помечается, параллельные записи не
теряются, синтетика не становится фактом, отзыв ломает `check` и блокирует Stop-хук,
`impact`/`review` находят зависящие выводы и решения, отчёт собирается, MCP-сервер отвечает по
протоколу и отклоняет факт без источника так же, как CLI.
База знаний: факт переносится с источником, вывод агента — только гипотезой, синтетика и факты
без источника в базу не попадают, поиск учитывает морфологию, отзыв записи виден в `check`.
- Стоимость считается по журналам Claude Code и тарифам API (`tools/pricing.json`); в других
  средах расход вносится вручную `pf.py cost-add`.
- Синтетические интервью — только для гипотез.
