# Демо-проект: бриф МегаФона «Связь для близких и собственных устройств»

Сквозной прогон агента по брифу организаторов: запрос, сбор, варианты, выбор, перерыв с
продолжением в новом чате, стратегия, план проверки, решение, новые данные и пересмотр.

| Файл | Что внутри |
|---|---|
| `inbox/brief.pdf` | бриф организаторов без изменений |
| `inbox/brief.md` | тот же текст в Markdown: агент сверяет цитаты с ним; таблицы перенесены вручную |
| `new-data/support_causes_q1.md` | **учебные данные команды** для пересмотра: причины перебоев по обращениям |
| `new-data/billing_constraints.md` | **учебные данные команды** для пересмотра: ограничения системы расчётов |

Все числа брифа учебные. Файлы в `new-data/` придуманы командой: они нужны, чтобы показать
пересмотр решения при новых данных. В брифе их нет.

## Сценарий

**1. Запрос** (новая сессия `claude` в корне репозитория):

> /pf-start Нужно решить, кому из клиентов вымышленного оператора помочь со связью в первую
> очередь — семьям или владельцам нескольких номеров, что изменить и стоит ли вкладывать деньги.
> Бриф в examples/megafon-brief/inbox (возьми brief.md, PDF — тот же текст). Результат — для
> руководителя направления: решение о пилоте к концу 1-го квартала, решение о расширении вместе
> с финансами к концу 2-го. Нужен полный разбор: отдельные продуктовая и коммуникационная
> стратегии, план проверки, план по кварталам и ориентир на конец третьего года. Итоговый
> документ собери по пяти частям брифа.

**Ответы PM на вопросы агента:**
- цель — выйти на годовую цель валовой прибыли 285 млн руб. (не хватает 6 млн к прогнозу 279)
  и поднять активные семейные группы; ставка — 500 руб. за дополнительный оплаченный месяц номера;
- получатель — руководитель направления, во втором квартале — вместе с финансовой командой;
- ограничения — только бриф и открытые источники; ресурсы — как в брифе (3 человеко-месяца
  разработки во 2-м квартале, дизайнер и аналитик по половине ставки, тестирование не подтверждено);
- критерии — польза для клиента, вклад в прибыль за плановый год, объём разработки, риск для
  данных и согласий, скорость первых результатов.

**2. Перерыв.** Агент останавливается на выборе варианта. Выберите вариант и закройте сессию.
Новый терминал, `claude`, «продолжим».

**3. Новые данные** после решения:

```bash
python3 tools/pf.py status          # slug проекта
cp examples/megafon-brief/new-data/* projects/<slug>/inbox/
```

> Пришли новые данные: разбор обращений о перебоях и ответ владельца системы расчётов. Что меняется?

Ожидаемое: допущения о причинах перебоев заменены данными; `impact` показывает выводы и решения,
которые на них опирались; задержка остатка до 6 часов и 3 из 5 тарифов меняют состав пилота
или выбор первой проблемы; данные обращений используются с оговоркой — только обратившиеся.

**4. Итог.** `python3 tools/pf.py check --release`, `python3 tools/pf.py cost`,
`python3 tools/pf.py report --html`.
